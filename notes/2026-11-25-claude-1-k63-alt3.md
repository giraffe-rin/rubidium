# 予想 K63：v2(m+1) = 3、v2(11u+1) ≥ 4 偶数の場合の交互型の条件

## 取りかかった理由

交互型の分類は、Lean で次のところまで確かめた（PR #406・#408・#410）。
- K10c：v2(m+1) = 3 で交互型なら、u ≥ 3、v2(9u+1) は奇数（= 1）、v2(11u+1) は偶数。
- K10 (a)：v2(11u+1) = 2（u ≡ 1 (mod 8)）なら交互型。

残るのは、v2(9u+1) = 1 で v2(11u+1) = 2e（e ≥ 2）の場合。WIP 上限（未査読の証明 PR が 5 件）のため、証明ではなく数値で条件を探した。

### 予想 K63 `[予想]`

m + 1 = 8u（u 奇数）、v2(9u+1) = 1、v2(11u+1) = 2e（e ≥ 2）、Y = (11u+1)/2^{2e} とする。
- (1) e = 2 で Y ≡ 1 (mod 4) なら、交互型。u ≤ 20000 で 313 個すべて。
- (2) e ≥ 3 で Y ≡ 3 (mod 4) なら、交互型でない。u ≤ 20000 で 105 個すべて。
- ほかの類（e = 2 で Y ≡ 3、e ≥ 3 で Y ≡ 1）は混在する。K9 の木のような、もっと深い量で決まると思われる。

確かめた範囲：u ≤ 20000（m ≤ 159999）。漸化式 R（K8 が前提）による。u ≤ 1200 は直接の DP でも一致した。

## 追記（2026-11-25）：証明の形を探した結果

### (1) の場合
K10 (a) と同じように、有限個の距離の所属を並べた。距離は u、2u、3u、6u、h、X₁、8Y、4Y、2Y、Y、h + 2Y など。
その結果、ブロックによって所属が変わる距離があった。たとえば u = 77 のブロック 1 では、(a + 4Y, 4Y) が N になる（ほかのブロックでは P）。
したがって、K10 (a) のように「どのブロックでも同じ事実の集合」を作る形では閉じない。

### (2) の場合
- 調べた 14 個のすべてで、最初に交互から外れる n は 2(2m+3) + (m+1) だった。
  つまり 4 番目のブロックで (c₂ + h, h) が N になり、行 c₂ + (m+1) がすべての p で P になる。
- `code/k63_explain.js` で、なぜ N になるかを手で説明する木を出した（`data/k63_explain_157.txt`・`data/k63_explain_349.txt`）。
- 木には、次の 2 種類の鎖が出てくる。
  - X₃ = 2^{e−1}·Y から 4Y まで、半分ずつ下る鎖。長さは e とともに伸びる。
  - h + 4Y を、奇数になるまで 2 で割り続ける鎖。長さは v2(u + Y) などの u ごとの量で決まる。
- そのため、K11 の `g_iter` のような 1 本の帰納法では足りず、u ごとの深い量を追う必要がある。
