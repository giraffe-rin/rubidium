# K29.3 の 3 値の計算の依存の範囲

## やったこと

- 定理 K29.3（`notes/2026-11-23-claude-1-k29-general.md`）の 3 値の計算は、距離 c·u をすべて（c < 2^v）計算していた。
  - そこで、ブロック L の h を決めるのに実際に参照する (ブロック n, c) だけを、遅延評価で集めた（`code/k29_cone.js`、`data/k29_cone.txt`）。
- 5 ≤ v ≤ 17 と u ≡ 1, 5 (mod 8) で調べた。

**前提**：定理 K29.3（`[非形式証明]`、計算機による証明書つき、未査読）。

## 結果

### 観察 K30 `[予想]`（5 ≤ v ≤ 17 で確かめた事実）

**u ≡ 1 (mod 8) の場合**
- 参照する (ブロック, c) の個数は、ちょうど 2^{L+1} − 3（L = (v+1)/2）。v = 5, 7, …, 17 で 13、29、61、125、253、509、1021。
- ブロック 1 で参照する奇数の c は、c₁ := (2^v + 1)/3 の 1 つだけ。
  - c₁ ≡ 3 (mod 4) で、c₁ + 1 ≡ 4 (mod 8) となる（例：v = 5 で 11、v = 7 で 43）。
  - よって 3 値の規則では c₁u ∈ S_1 と「入る」に決まる。
  - ほかにブロック 1 で参照するのは 2c₁ だけ。
- つまり、u ≡ 1 (mod 8) では、h の所属は次の 2 つだけから決まっている。
  - 1 つの事実「c₁u ∈ S_1」
  - E 型のブロックの (i)(ii)
  - 2^{L+1} − 3 個の距離の集まりは v について規則的に増える。たとえば、v のブロック 1 の c₁ = (2^v+1)/3 は、v+2 では 4c₁ − 1 になる。

**u ≡ 5 (mod 8) の場合**
- 参照する距離の個数は 16、43、105、253、625、1618、4440（v = 5〜17）で、2^{L+1} − 3 より多く、増え方も速い。
- ブロック 1 で参照する奇数の c は多数あるが、どれも 3 値の規則で決まっている。そうでなければ、h が「不明」になるはずである。

## 確かめたこと

- `data/k29_cone.txt` のすべての行で、ブロック L の h は「入る」と決まった。K29.3 と一致する。
- u ≡ 1 (mod 8) の参照の個数は、7 つの v のすべてで 2^{L+1} − 3 と一致した。
