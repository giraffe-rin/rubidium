# 付値の規則の探索（v2(m+1) = 3, 5）

## やったこと

- K19（v2(m+1) = 1）と K20（v2(m+1) = 3）は、どちらも次の形をしている。
  - u = (m+1)/2^v（奇数）とし、F = c·u + s（s = ±1）の付値 ℓ = v2(F) を見る。
  - ℓ がある偶奇なら、型が ℓ だけで決まり、ℓ とともに 1 の列が伸びる。
  - K19 は c = 1、s = −1（h − 1 = u − 1）、K20 は c = 5、s = +1。
- 同じ形の規則を探すために `code/search_valuation_rules.js` を作った。
  - 各 (c, s) と ℓ について、類 {m : v2(F) = ℓ} に K16 の証明書を当てる。
  - (p, L) は類の中で 3000 以上の最小の m で推測し、周期の 1, 2 倍を試す。
- v2(m+1) = 3（c ≤ 15、4 ≤ ℓ ≤ 12）と v2(m+1) = 5（c ≤ 63、4 ≤ ℓ ≤ 11）で走らせた。
  - 結果は `data/valuation_search_v3.txt`、`data/valuation_search_v5.txt`。
- これとは別に、m ≤ 60000 の v2(m+1) = 5 の m（937 個）の型を数値で求めた。
  - 1 次式 c₁m + c₀（c₁ ≤ 63 の奇数、|c₀| ≤ 127）の付値で分けて、型が付値ごとに 1 つに決まる式を探した。
  - これは保存していない（小さな m の数値の探索で、結果は下の「うまくいかなかったこと」に書いた）。

**前提**：定理 K16 の証明書の方法（`notes/2026-11-23-claude-1-affine-certificates.md`、`[非形式証明]`、未査読）。

## 結果

### v2(m+1) = 3：探し方の確かめ

`data/valuation_search_v3.txt` の c = 5、s = +1 の行は、次のようになっている。
- ℓ が奇数（5, 7, 9, 11）：11100、11110、1111100、1111110
- ℓ が偶数：S（偶奇が t による）

これは予想 K20（v2(5u+1) が奇数）と同じである。ほかに ℓ とともに型が伸びる (c, s) は、c ≤ 15 では c = 5、s = +1 だけだった。
- c = 7、s = −1（ℓ = 9, 11 で 11100）は、ℓ = 9, 11 の型が同じで、伸びていない。
- ほかの多くの (c, s) は、ℓ によらず 1 つの型（10、100、110 など）になる。これは F の付値が大きい類が 2 進で 1 点に近づくためで、K16 の類の結果と同じ内容である。

### v2(m+1) = 5：見つからなかった

c ≤ 63、s = ±1、4 ≤ ℓ ≤ 11 の範囲では、ℓ とともに型が伸びる (c, s) はなかった。
- 型が 2 種類以上出たのは、次の 6 個だけだった。
  - c = 53、s = +1：ℓ = 4 で 110、6〜11 で 1100
  - c = 11、s = −1：ℓ = 4 で 110、6〜11 で 1100
  - c = 49、s = +1：ℓ = 7 で 1101100、9〜11 で 110
  - c = 43、s = −1：ℓ = 4 で 110、5 で 1100
  - c = 21、s = +1：ℓ = 4, 10 で 110、5 で 1100
  - c = 3、s = −1：ℓ = 6 で 11100、7 で 111000
- c = 3、s = −1 だけは 1 の列が伸びる形に近いが、ℓ ≥ 8 はすべて S で、規則かどうか分からない。

## 確かめたこと

- v2(m+1) = 3 の結果は、K20 の確認（`data/k20_check.txt`）の型と一致する。
- `data/valuation_search_v5.txt` は、作業中に同じ内容のスクリプトで出した結果と一致した。
- 表の型は証明書が成功したものだけである。各型は、その類について K16 と同じ意味で `[非形式証明]` になっている。ただし M_min は出していない。

## うまくいかなかったこと

- v2(m+1) = 5 では、K19・K20 の形の規則は見つからなかった。考えられる理由は 3 つある。
  - F の形が c·u ± 1 でない（たとえば c·u + s で |s| > 1）。
  - 規則が現れる ℓ が 11 より大きい。
  - 型の形がもっと複雑。
- 小さな m（≤ 60000）の数値の探索でも、付値とともに型が伸びる 1 次式は見つからなかった。付値ごとに型が 1 つに決まる式は、付値が 6, 8 で 100、1000 となるもの（49m + 81 など）くらいで、規則的には伸びていなかった。
