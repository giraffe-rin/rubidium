## 数学的健全性の確認

### 1. `prove(m, w)` の健全性（`m` 奇数、`w` 長さ `L`、末尾に 0 が `s ≥ 1` 個）

- **帰納仮定（周期開始ブロック `B`）**：
  - `(G)`：`d` 奇数なら `d ∈ S_B`、また `1 ≤ v2(d) ≤ min(2s - 1, v - 1)` なら `d ∈ S_B ⇔ v2(d)` 偶数（`v = v2(m + 1)`）。
  - `(A)`：有限集合 `A` の各 `d` について `S_B(d)` が所定の値 `val(d)` をとる。
- **基底段階（`B = 0`）**：
  - 定理 K3 より `S_0(d) ⇔ v2(d)` 偶数であるため `(G)` は成り立つ。
  - `(A)` の各要素の値も `v2(d)` 偶数で与えているため、ブロック `0` は `(G)(A)` を満たす。
  - 条件 `(0)`：`m` 奇数より `g_0 = m + 2 ⇔ h = (m + 1)/2 ∈ S_0 ⇔ v2(h)` 偶数。これが `w[0]` と一致することを確認している。
- **帰納段階（`B → B + L`）**：
  - ブロック `B` が `(G)(A)` を満たし、`g_B = w[0]` であると仮定する。
  - 遅延評価 `S(i, d)`（`1 ≤ i ≤ L`）は K8 の遷移規則 `R` のみを適用し、`B` の事実として参照したものがすべて `(G)` または `(A)` で一意に決まった（`unknown` が残らない）ことを保証する。
  - 条件 `(1)` により、各 `i = 1, ..., L` で `S_{B+i}(h)` が `w[i mod L]` と一致するため、帰納的に間隔 `g_{B+1}, ..., g_{B+L}` が `w[1], ..., w[L-1], w[0]` と一致することが正当化される（直前の間隔 `g_{B+i-1}` は先行ステップで確定済み）。
  - 特にブロック `B + L` の直前 `s` ブロックの間隔は `w[L-s] = ... = w[L-1] = 0` すなわちすべて `m + 1` である。`m` が奇数なので補題 `Q_s`（PR #147 / #202 `[査読済み]`）により、ブロック `B + L` で `(G)` が成立する。
  - 条件 `(2)` により、`(A)` のすべての `d` で `S_{B+L}(d) = val(d)` が再現される（かつこの評価でも未知事実は出ない）。
- よって帰納法により、すべての `k ≥ 0` でブロック `kL` は `(G)(A)` を満たし、全ブロックの間隔列は純周期 `w` のくり返しとなる。**数学的健全性は完全である。**

### 2. `prove2(m, w)` の健全性（`m` 奇数、出発点をブロック `L` に取る版）

- **前段 `(0′)`**：ブロック `0` で K3 をそのまま用い、`(0)` で `g_0 = w[0]` を確認したうえで、ブロック `j = 1, ..., L` について `R` による厳密評価 `T(j, h)` が `w[j mod L]` と一致することを直接確認する。よってブロック `0, ..., L` の間隔は `w[0], ..., w[L-1], w[0]` と確定する。
- **基底段階（`B = L`）**：
  - ブロック `L` の直前 `s` ブロックは `(0′)` によりすべて間隔 `m + 1` なので、補題 `Q_s` によりブロック `L` で `(G)` が成立する。
  - `(A)` の各要素 `d` の値には、K3 から正確に計算した `T(L, d)`（ブロック `L` での実際の所属値）を採用しているため、ブロック `L` は `(A)` も満たす。
- **帰納段階（`B → B + L`、`B = kL, k ≥ 1`）**：`prove` と全く同様に、`(1)` でブロック `B+1, ..., B+L` の間隔一致、補題 `Q_s` でブロック `B+L` の `(G)`、`(2)` で `(A)` の再現が成り立つ。
- よってブロック `0..L` は `(0′)`、ブロック `L` 以降は帰納法により、全ブロックの間隔列が純周期 `w` と確定する。**数学的健全性は完全である。**

## 実装監査で発見した堅牢化すべき点（`code/period_induction.js`）

`prove`・`prove2` の数学的アルゴリズム自体は健全であるが、`code/period_induction.js` の実装に**上限 `maxFacts` 超過時に偽陽性を生みうるエッジケース**が 3 箇所見つかった（なお、後述の厳密独立検証で最大評価事実数は `50,693 ≪ 3,000,000` であったため、**PR #237・#239・#241 のすべての結果には影響していない**）：

1. **`A` 再現ループ後の `tooMany` チェック欠落**（`prove` 24 行目付近 / `prove2` 56 行目付近）：
   `for (const [ds, val] of A)` 内で `S(L, BigInt(ds))` が `memo.size > maxFacts` を踏むと `tooMany = true` にして `false` を返す。もし残りの `val` がたまたま `false` であれば `got !== val` に引っかからずループを抜け、直後に `if (tooMany)` の検査がないため `{ ok: true }` を返しうる（さらに再帰途中で `unknown || tooMany` が立ったときも `memo.set(key, r)` が実行される点も、`tooMany` 検査漏れと組み合わさると危険）。
2. **`prove2` の `(0′)` ループおよび 2 回目の `T(L, unknown)` での `over` チェック欠落**：
   - `(0′)` の `for (let j = 1; j <= L; j++) { if ((T(j, h) ? '1' : '0') !== w[j % L]) ... }` では、もし `over` が発生したブロックでたまたま `w[j % L] === '0'` だと `T(j, h)` の戻り値 `false` (`'0'`) と一致してしまい、`over === true` のままループを通過しうる。ループ先頭または直後に `if (over) return { ok: false, ... }` を入れるべきである。
   - 2 回目の `if (unknown) { A.set(unknown.toString(), T(L, unknown)); continue; }` でも直後に `if (over)` のチェックが抜けている（1 回目の `if (unknown)` には入っている）。
3. **入力 `m` の奇数性ガードの明示**：
   `prove` / `prove2` のブロック 0 判定コメントに「`m` が偶数なら `g_0 = m+1`」とあるが、本体の `S` / `T` は `m` 奇数用の遷移（`h = (m+1)/2`、`g = m+2 ⇔ h ∈ S_i`、および補題 `Q_s`）を前提としている。偶数 `m` が渡されないよう関数冒頭で `if (m % 2n === 0n) return { ok: false, why: 'm が偶数' }` と明示的に弾くべきである。
