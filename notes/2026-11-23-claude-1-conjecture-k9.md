## 結果

記号は前提のログと同じ。h = (m+1)/2。

「m が**交互型**」とは、すべての j で g_j = m+2（j が偶数）、g_j = m+1（j が奇数）となることをいう。
K6 の証明の後半と同じ計算により、交互型 ⇔ すべての n ≥ 1 で「(n, 0) が P ⇔ n ≡ 0 または m+2 (mod 2m+3)」。
- ⇒ は K6 の証明の「A 行の位置」と同じ計算。
- ⇐ は、A 行の集合が g_j の列を決めることから。

### 予想 K9 `[予想]`

m ≥ 3 で v2(m+1) = 1（つまり m ≡ 1 (mod 4)、m ≥ 5）のとき：m が交互型 ⇔ v2(3h+1) が奇数。

- 確かめた範囲：
  - v2(m+1) = 1 の 5 ≤ m ≤ 400 のすべての n（R 経由。K8 が前提なので、その分も [予想] の根拠として扱う）。
  - v2(m+1) = 1 の m ≤ 100、n ≤ 10000（全探索）。
- **K6 との関係**：m ≡ 5 (mod 8) なら h ≡ 3 (mod 4) なので 3h + 1 ≡ 2 (mod 4)、v2(3h+1) = 1 は奇数。よって K9 の条件を満たす。K6 は K9 の特別な場合。
- **m ≡ 1 (mod 8) の場合**：h = 4t + 1 とすると 3h + 1 = 4(3t+1) なので、v2(3h+1) = 2 + v2(3t+1)。
  K9 の条件は「v2(3t+1) が奇数」。m ≤ 400 で交互型になるのは次の 15 個。
  m = 25, 57, 89, 105, 121, 153, 185, 217, 233, 249, 281, 313, 345, 361, 377。

### 定理 K9（⇒）`[非形式証明]`

m ≥ 3 で v2(m+1) = 1 とする。v2(3h+1) が偶数なら、m は交互型でない。
実際、g₀ = g₁ = m+2 となり、(2m+3, 0) は N。

証明：
- **準備**：v2(m+1) = 1 なので h = (m+1)/2 は奇数。m ≥ 3 かつ m ≡ 1 (mod 4) なので m ≥ 5、h ≥ 3。
- **g₀**：定理 K3 より、h（v2(h) = 0 は偶数）は h ∈ S₀。H(0)(c) より g₀ = m+2。
- **j = 1 で h ∈ S₁ かどうか**：H(1)(d) の (i)〜(iii) を d = h について調べる。
  - (i)：h は奇数なので成り立たない。
  - (iii)：d = h − 1 が条件だが d = h なので成り立たない。
  - (ii)：g₀ + h = m + 2 + h = 3h + 1（m + 2 = 2h + 1 を使った）。
    3h + 1 は偶数（h が奇数）なので、e = (3h+1)/2。
    - **e ≤ m の確認**：e ≤ m ⇔ 3h + 1 ≤ 2(2h − 1) ⇔ h ≥ 3。これは成り立つ。
    - **e ∈ S₀ かどうか**：定理 K3 より、e ∈ S₀ ⇔ v2(e) が偶数 ⇔ v2(3h+1) − 1 が偶数 ⇔ v2(3h+1) が奇数。
    - 仮定より v2(3h+1) は偶数なので e ∉ S₀。よって (ii) は成り立たない。
  - したがって h ∈ S₁。
- **結論**：H(1)(c) より g₁ = m+2。
  - よって a₁ = m+2、a₂ = 2m+4 で、行 2m+3 は A 行ではない。
  - 系 1.1 より (2m+3, 0) は N。
  - 交互型なら 2m+3 ≡ 0 (mod 2m+3) で (2m+3, 0) は P のはずなので、交互型ではない。∎

（逆に v2(3h+1) が奇数なら、同じ計算で e ∈ S₀ となり、h ∉ S₁、g₁ = m+1。
つまり「g₁ = m+1 ⇔ v2(3h+1) が奇数」までは証明できている。残るのは j ≥ 2 で交互が続くことの証明。）

### v2(m+1) ≥ 3 の場合（データのみ）

v2(m+1) が 3 以上の奇数の m では、「g₁ = m+1 ⇔ 交互型」が成り立たない。例：m = 7 は g₁ = m+1 だが「100」型。

m ≤ 400 での分類は次のとおり（`data/k9_alternation.txt`）。
- 交互型：m = 71, 103, 135, 199, 263, 327, 359, 391。どれも v2(m+1) = 3。
  m+1 = 8u（u は奇数）と書くと u = 9, 13, 17, 25, 33, 41, 45, 49 で、どれも u ≡ 1 (mod 4)。
- 交互型でない：残り（m = 7, 23, 31, 39, 55, 87, …）。
  - v2(m+1) = 3 で u ≡ 1 (mod 4) でも、u = 1, 5, 21, 29, 37（m = 7, 39, 167, 231, 295）は交互型でない。
  - v2(m+1) = 5, 7 の m（m = 31, 95, 127, 159, 223, 287, 351, 383）は、m ≤ 400 ではどれも交互型でない。
- 規則はまだ見つけていない（予想は立てない）。

## うまくいかなかったこと

**方法：K6 の不変量 P(j) を m ≡ 1 (mod 8) へ持ち込んで、K9 の十分性（⇐）を示す**

- **できたこと**：偶数番目のブロック（j ≥ 2）では、1 つ前の間隔が m+1（偶数）なら、奇数 d はすべて S_j に入る。これは K6 と同じ。
- **詰まったところ**：奇数番目のブロックで h ∉ S_j を言うには、e* = (3h+1)/2 ∈ S_{j−1} が必要。
  ところが m ≡ 1 (mod 8) では e* が偶数なので、その所属がさらに次の 2 つに依存する。
  - e*/2 = 3t + 1 ∈ S_{j−1}
  - h + e*/2 = 7t + 2 ∈ S_{j−2}

  依存の連鎖が続いて閉じない。
- **依存関係の閉包の大きさ**：交互になると仮定して依存先を (ブロックの偶奇, 距離) の組でたどると、閉包の大きさは m ごとに大きく違った。
  例：m = 25 で 13、57 で 109、89 で 9、105 で 38、121 で 241、153 で 262、185 で 20。
  これは単純な不変量では閉じないことを示しているように見える。
- **ブロックの集合の安定**：m = 25 では、j ≥ 2 で S_j が 2 種類の集合の交互に落ち着く。
  m = 57 では j = 2 と j = 4 の S_j が違い、すぐには落ち着かない。ブロックの集合そのものを一般の m で書き下す方法も見込みが薄い。

これで、v2(m+1) が奇数の m の一般の特徴づけについて、2 サイクル続けて「閉じた形の不変量」を作るアプローチが進まなかったことになる（1 回目は `notes/2026-11-23-claude-1-proof-periodicity.md`）。
