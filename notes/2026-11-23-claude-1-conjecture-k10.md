# 予想 K10：v2(m+1) = 3 の交互型

## やったこと

- v2(m+1) = 3 の m（m + 1 = 8u、u は奇数）について、実装 C（`code/solver_rowtype.js`）で開始局面の列を調べた。
  - 範囲は m ≤ 1000（63 個）、n ≤ min(200000, 60·(2m+3))。
  - コードは `code/check_k10.js`、結果は `data/k10_v2eq3.txt`。
- ブロック 1 の間隔 g₁ の式を証明した（命題 K10a）。
- それを使い、u ≡ 3 (mod 8) では交互型にならないことを示した（系 K10b）。

**前提**：`notes/2026-11-23-claude-1-proof-structure.md` の主張 H(j) と定理 K3。どちらも `[非形式証明]`（未査読）。

「交互型」の意味は `notes/2026-11-23-claude-1-conjecture-k9.md` と同じ。
交互型 ⇔ すべての n ≥ 1 で「(n, 0) が P ⇔ n ≡ 0 または m+2 (mod 2m+3)」。

## 結果

### 命題 K10a（g₁ の式）`[非形式証明]`

m + 1 = 8u（u は奇数）のとき：
- g₀ = m+2
- g₁ = m+2 ⇔ v2(9u+1) が偶数

証明：
- **準備**：h = (m+1)/2 = 4u なので v2(h) = 2。m = 8u − 1 ≥ 7。
- **g₀**：定理 K3 より h ∈ S₀（v2(h) = 2 は偶数）。H(0)(c) より g₀ = m+2 で、g₀ は奇数（m + 2 = 8u + 1）。
- **ブロック 1 の 3 つの距離 u, 2u, 4u = h**：どれも 1 以上 m 以下。H(1)(d) の (i)〜(iii) を、この順に調べる。
  (iii) の対象は d = h − 1 = 4u − 1 だけで、u, 2u, 4u のどれとも等しくない（4u − 1 は奇数で u ≥ 1 と異なり、2u, 4u は偶数）。よって (iii) はどれにも効かない。
  - **d = u（奇数）**：
    - (i)：u は奇数なので成り立たない。
    - (ii)：g₀ + u = 9u + 1 は偶数で、e = (9u+1)/2。
      e ≤ m ⇔ 9u + 1 ≤ 16u − 2 ⇔ 7u ≥ 3 なので、e ≤ m。
      定理 K3 より、e ∈ S₀ ⇔ v2(e) が偶数 ⇔ v2(9u+1) が奇数。
    - よって u ∈ S₁ ⇔ e ∉ S₀ ⇔ v2(9u+1) が偶数。
  - **d = 2u**：
    - (i)：「u ∈ S₁」。
    - (ii)：g₀ + 2u = 10u + 1 は奇数なので成り立たない。
    - よって 2u ∈ S₁ ⇔ u ∉ S₁。
  - **d = 4u = h**：
    - (i)：「2u ∈ S₁」。
    - (ii)：g₀ + 4u = 12u + 1 は奇数なので成り立たない。
    - よって h ∈ S₁ ⇔ 2u ∉ S₁ ⇔ u ∈ S₁ ⇔ v2(9u+1) が偶数。
- **結論**：H(1)(c) より、g₁ = m+2 ⇔ h ∈ S₁ ⇔ v2(9u+1) が偶数。∎

### 系 K10b `[非形式証明]`

m + 1 = 8u で v2(9u+1) が偶数なら、m は交互型でない。特に u ≡ 3 (mod 8) なら交互型でない。

証明：
- 命題 K10a より g₀ = g₁ = m+2 なので、a₂ = 2m + 4 で、行 2m+3 は A 行でない。
  よって (2m+3, 0) は N で、交互型の条件（2m+3 ≡ 0 で P）に反する。
- u ≡ 3 (mod 8) なら 9u + 1 ≡ u + 1 ≡ 4 (mod 8)（9 ≡ 1 (mod 8) なので）。よって v2(9u+1) = 2 は偶数。∎

### 予想 K10 `[予想]`

m + 1 = 8u（u は奇数）のとき：
- (a) u ≡ 1 (mod 8) かつ u ≥ 9 なら、m は交互型。
- (b) u ≡ 7 (mod 8) なら、m は交互型でない。

（u ≡ 3 (mod 8) は系 K10b で示した。u = 1、つまり m = 7 は交互型でない。間隔は 1, 0, 0, 1, 0, 0, …。）

- 確かめた範囲：v2(m+1) = 3 の m ≤ 1000（63 個）、各 m で n ≤ min(200000, 60·(2m+3))。実装 C による（`data/k10_v2eq3.txt`）。
  - (a) を満たす m：71, 135, 199, 263, 327, 391, 455, 519, 583, 647, 711, 775, 839, 903, 967。すべて交互型だった。
  - (b) を満たす m（u = 7, 15, 23, …, 119、15 個）は、すべて交互型でなかった。
- u ≡ 7 (mod 8) の注意：v2(9u+1) が奇数（3, 5, 7）で g₁ = m+1 になる m もある（例：u = 15 で v2(136) = 3）。
  それでも交互型にはならない。間隔は 1, 0, 0, 1, … のように、どこかで崩れる。理由はまだ分からない。
- **u ≡ 5 (mod 8)** はまちまち。m ≤ 1000 で交互型なのは u = 13, 45, 77, 93（m = 103, 359, 615, 743）だけ。
  u mod 32 などでは分類できなかった。例：u = 13 と u = 109 はどちらも ≡ 13 (mod 32) だが、u = 109 は 6 個目の間隔で崩れる。予想は立てない。

### 比較：v2(m+1) = 1 の場合（K9）

- v2(m+1) = 1 の場合（K9）は「g₁ = m+1 ⇔ 交互型」だった。
- v2(m+1) = 3 では、g₁ = m+1 でも交互型でない m がある。例：u = 1, 5, 21, 29, 37, …（u ≡ 5 (mod 8) の多く）と u ≡ 7 (mod 8)。
- そのため v2(m+1) = 3 では、ブロック 2 以降の振る舞いまで見ないと決まらない。

## うまくいかなかったこと

- **u ≡ 5 (mod 8) と u ≡ 7 (mod 8) の分類**：u を 32、64 で割った余りで分類しようとしたが、交互型かどうかはそれでは決まらなかった（上の u = 13 と 109 の例）。
- ブロック 2 での h の所属を K10a と同じ方法で計算しようとしたが、依存する距離が増えて場合分けが閉じなかった。
  これは前回打ち切った「閉じた形の不変量」のアプローチ（STATUS.md「試して駄目だった方法」）と同じ壁なので、深追いしなかった。
