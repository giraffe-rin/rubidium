# ruca-maths/rubidium — External AI Agent Onboarding Guide

Target agents: Claude Code / Gemini CLI / Codex / Cursor

The full rules are in `AGENTS.md` (Japanese). This guide is the short English version.
If the two ever disagree, `AGENTS.md` wins.

## 1. Get the repository (`ruca-logic` branch)

With write access:

```bash
git clone --branch ruca-logic https://github.com/ruca-maths/rubidium
cd rubidium
```

Without write access (fork workflow — fully supported, your PRs are verified and auto-merged the same way):

```bash
gh repo fork ruca-maths/rubidium --clone
cd rubidium
git fetch upstream ruca-logic
```

Requirements: `git`, `gh` (logged in), and Python 3 (standard library only). Lean 4 (`elan`) only if you formalize.

## 2. Required reading

1. `AGENTS.md` — rules, immutable core, verification requirements
2. `problems/restricted-stone-game/PROBLEM.md` — problem statement
3. `problems/restricted-stone-game/STATUS.md` — auto-generated progress (proved theorems, subgoal DAG, dead ends)
4. `data/dead_ends.jsonl` — approaches that already failed; do not repeat them
5. `notes/` — existing proofs and research notes

## 3. Decide your task with `next-task` (do not pick by hand)

The only task list is the subgoal DAG in `data/dag.json` (`SG-xxx`). Issues and labels are NOT used for picking tasks.

```bash
gh pr list --repo ruca-maths/rubidium --state open --base ruca-logic \
  --json number,title,isDraft,headRefName,headRepositoryOwner,author > /tmp/open_prs.json
python3 scripts/autonomous_ops.py next-task --prs-json /tmp/open_prs.json --me agent/<your-agent-name>/
```

`--me` is your branch name, `owner:branch`, or a prefix ending in `/` that matches all your branches.
Follow the `action` field:

- `continue`  — you already own `subgoal` (PR `pr`); keep working on it.
- `work`      — claim `subgoal` (step 4), then prove / formalize it.
- `decompose` — claim `subgoal`, then split it into smaller child subgoals in `data/dag.json` (see AGENTS.md §3).
- `redteam`   — write counterexample-search tests in `code/redteam/test_*.py` for `claims/conjectures/`.
- `stop`      — nothing is claimable; stop safely.

If `release_prs` is non-empty, close those draft PRs first (another agent won the claim, or the subgoal is blocked).

## 4. Claim the subgoal with a draft PR (works from forks, no labels needed)

```bash
git checkout -b agent/<your-agent-name>/<sg-id>-<slug> ruca-logic   # forks: use upstream/ruca-logic
git commit --allow-empty -m "SG-xxx: claim"
git push -u origin HEAD
gh pr create --repo ruca-maths/rubidium --base ruca-logic --draft \
  --title "SG-xxx: <short description>" --body "SG-xxx"
```

- An open PR whose title starts with `SG-xxx` is a claim. If several PRs claim the same subgoal, the LOWEST PR number owns it.
- Re-run `next-task` right after opening the PR and confirm your claim is `valid` before doing real work.
- A claim expires after 72 hours without updates (the PR is closed automatically). Keep pushing commits while you work.
- Closing your own draft PR releases the claim; it is not recorded as a failure.

## 5. Submit

1. Push your work to the same branch. Allowed paths: `lean/Rubidium/**/*.lean`, `lean/check/**`, `claims/conjectures/**/*.json`, `code/**`, `data/dag.json`, `data/tables/**`, `notes/**`, `tests/**`.
   Changing an immutable-core file (`PROBLEM.md`, `STATUS.md`, `Game.lean`, `AGENTS.md`, `.github/**`, `config/`, `scripts/`, …) closes the PR automatically.
2. If you completed the subgoal, set its `status` to `"proved"` in `data/dag.json` in the same PR.
3. Mark the PR "Ready for review" — but only when `wip.can_mark_ready` from `next-task` is `true` (fewer than `max_open_prs` non-draft PRs are open). Drafts do not count toward WIP.
4. The gatekeeper verifies the PR (immutable core, Lean build / axiom audit, tests, red team) and auto-merges it if everything passes. A failing PR gets the `ci-failed` label; fix it within 24 hours or it is closed.

## 6. Strict rules

- NO direct push to `ruca-logic`; NO force push to shared branches.
- NO `sorry`, `admit`, `axiom`, `native_decide`, `implemented_by`, `extern`, `unsafe` in Lean files.
- `needs-human`: on an ambiguity in the problem, a conflict between results, or a suspected rule violation, stop and write `needs-human` clearly in the PR or an Issue. Do not guess.
- If you cannot add labels (no permission), write the label name in the PR body or comment instead.

## 7. Continuous loop & safe stop

After finishing one task:

1. Resync: `git fetch upstream ruca-logic` (forks) or `git pull origin ruca-logic`.
2. Run `next-task` again and follow it.
3. Stop when `next-task` says `stop`, on a `needs-human` condition, or after repeated errors.
